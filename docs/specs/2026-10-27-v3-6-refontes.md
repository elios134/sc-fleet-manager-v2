# Refonte de 6 pages — v3.6 (spec)

Validée par André le 28/10/2026. Variantes choisies le 27/10 sur la maquette `docs/design/maquettes-refonte-pages-2.html` :
**A** pour Missions, Inventaire, Comparateur, Pack et Actualités ; **B** pour le Journal.

## Objectif
Aligner les 6 pages restantes sur les modèles adoptés en v3.4 (liste + fiche fixe large, ou tableau +
fiche en fenêtre comme Ma flotte), sans perdre une seule fonction existante. Réussi quand chaque page
correspond à sa maquette et que la liste « Conservé » ci-dessous est entièrement vérifiable dans l'app.

## Ce qui existe déjà (vérifié dans le code le 27/10)

  groupes, `searchText`), `ShipDetailsModal` (fiche vaisseau + `extraActions`, `badges`, `footer`).
- **Missions** (`pages/MissionHub`, 1 353 l.) : 2 panneaux (liste 360 px + fiche). États persistés
  `intel.*` (recherche, factions, tri, filtre, page, mission choisie, onglet de fiche).

  `TradeJournal` (`createdAt`, `location`, `totalPrice`).
- **Inventaire** (`pages/Inventory`) : arbre des lieux (`ScopeRail`), vue tuiles ou liste, recherche
  « Où est mon… ? » (`useWhereIs` : catégories, récentes, lieux de l'objet), `ItemWhereCard` (mini-carte,

  Loadouts (`LoadoutCompareView`, inchangé).
- **Pack** (`pages/PackDetailPage.tsx`, 301 l.) : `get_pack_detail` → chiffres, type, date, CCU,
  vaisseaux (assurance), recherche, « afficher plus », `ShipDetailsModal` au clic.
- **Actualités** (`pages/NewsPage.tsx`, 176 l.) : `get_rsi_server_status` + `get_rsi_news`, bouton
  Actualiser ; route `/news` hors navigation, ouverte depuis l'accueil.

## Fonctionnalités

### 1. Missions — liste + fiche fixe (A)
- Barre : recherche, factions (choix multiple), tri (réputation, durée, A→Z), compteur « N missions ·
  M factions » ; puces Toutes / Loot / Objectifs / Favoris avec compteurs.
- Tableau : mission (★ favori, pastilles illégal / loot), faction, système, récompense, durée,
  réputation. Paquets de 50 avec « Afficher plus » (fin des pages numérotées).
- Fiche fixe (SidePanel) : titre, favori, pastilles faction / système / légalité, onglets **Détails**
  (contenu actuel de `DetailsTab` + `ReputationPanel`) et **Drop** (`DropTab`, plans → Crafting).
- Conservé : tout ce qui précède + états vides, erreurs, persistance `intel.*` (la page devient une
  limite d'affichage non persistée).

### 2. Journal — chronologie + bilan (B)
- En-tête : périodes 30 j / 90 j / Tout, bouton « Relire le Game.log ».
- Colonne principale : **une ligne par jour joué**, du plus récent au plus ancien : date, temps de jeu,
  nombre de sessions, véhicules utilisés, lieux, missions réussies, dépenses du jour.
- Fiche fixe à droite (SidePanel) : bilan de la période (temps de jeu, sessions, série actuelle et
  record, missions réussies / abandonnées / échouées, plans débloqués, dépenses), carte d'activité,
  véhicules / lieux / systèmes les plus utilisés, dépenses par boutique.
- Données : `get_journal_overview` renvoie en plus `days: [{ date, seconds, sessions, vehicles[],
  locations[], missionsCompleted, spent }]` (sessions rattachées au jour de leur début, UTC ;
  dépenses = achats `TradeJournal` du jour). Rien de stocké en plus.
- Conservé : tous les agrégats actuels (déplacés dans le bilan), état vide, chargement.

### 3. Inventaire — lieux + liste + fiche (A)
- En-tête : recherche « Où est mon… ? » (catégories, recherches récentes), pastille de suivi en direct.
- Gauche : arbre Sur moi / systèmes / lieux avec compteurs (`ScopeRail`).
- Centre : résumé du lieu + objets en tableau (vignette, nom, catégorie, quantité, vu il y a) ; bascule
  tuiles / liste conservée. Une recherche active filtre ce tableau sur tous les lieux.
- Fiche fixe à droite : objet choisi (image, catégorie), **où il se trouve** (tous les lieux et
  quantités), mini-carte, « Voir sur la carte » et « + Itinéraire » (logique de `ItemWhereCard`).
- Conservé : avertissement suivi coupé, états vides (pas de Game.log, inventaire vide + import),
  note de bas de page.

### 4. Comparateur — duel resserré (A)
- Ligne de sélection : A (avec « Mes vaisseaux » en tête), échange ⇄, B, filtre, Réinitialiser.
- Bandeau verdict : vignettes A et B et « A gagne N critères sur M » (égalité gérée).
- Tableau en miroir par groupe (vol, combat, logistique) à gauche ; radar dans une fiche fixe à droite.
- Mode Loadouts et la bascule Vaisseaux / Loadouts : inchangés. `?ship=` conservé.

### 5. Pack — comme Ma flotte (A)
- Fil d'Ariane vers Ma flotte, nom, type, date d'achat, mention CCU, recherche dans le pack.
- Bandeau : vaisseaux, LTI, fabricants, valeur.
- Tableau : vaisseau (vue de dessus, fabricant), rôle, pastille d'assurance (LTI / courte / mois).
  Paquets avec « Afficher plus » ; clic → `ShipDetailsModal` (inchangé).
- Conservé : chargement, identifiant invalide, pack introuvable.

### 6. Actualités — articles + serveurs (A)
- Articles en liste : image (masquée si absente), catégorie, date, titre, résumé, « Lire sur RSI ».
- Fiche fixe à droite : état global des serveurs et de chaque service (pastille de couleur + texte).
- Bouton Actualiser ; états chargement / vide / statut indisponible conservés.

## Architecture
- **Domaine (logique pure + tests)** :
  - `pages/MissionHub/lib/missionView.ts` : `filterMissions`, `sortMissions`, `missionCounts`
    (sorties de l'index actuel).
  - `pages/Journal/lib/days.ts` : `dayLabel`, `sortDays` ; Rust : regroupement par jour testé dans
    `journal_overview.rs`.
  - `pages/Inventory/lib/itemPlaces.ts` : `placesOfItem(state, key)` (lieux et quantités d'un objet).
  - `pages/Comparator/lib/verdict.ts` : `duelVerdict(duel)` (gagnant, score, égalité).
  - `pages/PackDetail/lib/packView.ts` : `filterPackShips`, `packInsuranceTone`.
- **Interface** : Pack et Actualités passent en dossiers (`pages/PackDetail/`, `pages/News/`), routes
  mises à jour. Composants nouveaux : `MissionTable`, `MissionSheet`, `JournalDays`, `JournalSummary`,
  `InventoryTable`, `ItemSheet`, `DuelBar`, `VerdictBanner`, `PackShipsTable`, `NewsList`,
  `ServerStatusPanel`. Les composants remplacés sont supprimés (pas de code mort).
- **Rust** : seul `get_journal_overview` change (champ `days`). SQL paramétré.
- i18n : clés plates fr / en, clés devenues inutiles supprimées.

## Erreurs et cas limites
- Liste vide après filtre : message « aucun résultat » ; la fiche affiche le premier élément visible
  ou rien.
- Journal sans Game.log : état vide actuel ; jour sans dépense : « — ».
- Inventaire : objet sans image → icône ; objet présent nulle part ailleurs → seule ligne « ici ».
- Comparateur : un seul vaisseau choisi → invite actuelle ; critère sans donnée → « — », non compté.
- Actualités hors ligne : message actuel, état des serveurs « indisponible ».
- Fenêtre < 1024 px : la fiche passe sous la liste (`SidePanelLayout`).

## Sécurité et confidentialité
Aucune donnée nouvelle envoyée au réseau ; le Journal lit davantage la base locale (sessions par jour).
CSP inchangée (images d'articles RSI déjà autorisées).
